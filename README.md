# crystal-mod

Серверная валюта «Хрусталики» для Minecraft-сервера **Runes & Rails** (NeoForge `1.21.1` / `21.1.228`). Мод — это только витрина в игре: вся экономика (баланс, курс конвертации, подписки, антидюп) считается на сайте, мод общается с ним по HTTP.

## Конвенции проекта

Структура и подходы подогнаны под остальные моды в `Xs_Mods` (см. `auth-mod`, `clans-mod`):

- плоский пакет `ru.alex.crystalmod`, без вложенных `item`/`registry`/`command`; исключения — `ru.alex.crystalmod.client` (классы экрана недоступны на выделенном сервере, их нельзя даже class-load'ить из безусловно выполняемого кода) и `ru.alex.crystalmod.net` (сетевые пакеты)
- свой JSON-конфиг через Gson (`config/Xs_Crystal/config.json`), не NeoForge `ModConfigSpec`/TOML
- `net.neoforged.gradle.userdev`, не `net.neoforged.moddev`
- `@Mod("crystalmod")` + однопараметрический конструктор `(IEventBus modBus)`

## Что умеет

### Банкнота (`CrystalNoteItem`)

Не стакуется — у каждой свой `serial` (UUID) и `value` (номинал) в data component. Сайт помнит статус каждого выпущенного `serial`, повторная сдача с другого аккаунта — тревога, а не повторное начисление.

Зачисление на баланс сайта — **только** через `/crystal deposit` или банкомат. **ПКМ по банкноте ничего не делает** — раньше депозит срабатывал по правому клику, но случайный клик мог депонировать банкноту, которую игрок просто хотел переложить или рассмотреть. Убрано намеренно.

### Команды

| Команда | Доступ | Что делает |
|---|---|---|
| `/crystal give <player> <serial> <value>` | op / RCON | выдать банкноту — сайт вызывает по RCON при выводе хрусталиков в игру; сигнатура зафиксирована в `config.php → crystals.give_command` сайта |
| `/crystal check` | все игроки | проверить банкноту в основной руке: подлинная / уже сдана (подозрение на дюп) / подделка (serial никогда не выпускался). Rate-limit 3/мин на игрока |
| `/crystal deposit <amount>` | op или право `crystalmod.command.deposit` | сдать банкноты из инвентаря на сумму `amount` (жадно, по возрастанию номинала), сдача — новой банкнотой |
| `/crystal withdraw <amount>` | op или право `crystalmod.command.withdraw` | вывести `amount` хрусталиков с баланса сайта банкнотами прямо в инвентарь |
| `/crystal market listchest <registry_id> <quantity> <price>` | op | выставить лот из содержимого сундука (или другого контейнера), на который смотрит игрок |

Права на `deposit`/`withdraw` зарегистрированы через штатный NeoForge `PermissionAPI`: если на сервере есть мост LuckPerms, права на конкретные группы работают сами, без единой правки этого мода. По умолчанию — только op.

### Банкомат (`CrystalATMBlock`)

- **Внести** — кладёшь банкноты в лоток (5 слотов) и вводишь сумму, мод сам выбирает минимально достаточный набор банкнот (жадно, по возрастанию номинала), сдача минтится одной новой банкнотой.
- **Снять** — списание с баланса сайта, банкноты выдаются напрямую в инвентарь (без RCON — банкомат физически рядом с игроком, доставка это просто ответ HTTP-запроса).
- Мини-плашка баланса над окном — кешируется на клиенте, обновляется лениво (не чаще раза в 15 сек), лишних запросов не создаёт.

### Торговый терминал (`MarketTerminalBlock`)

- **Выставить лот** — кладёшь предмет в слот, указываешь цену за штуку. Предмет исчезает из инвентаря сразу (мод уже держит его физически). Все данные предмета — зачарования, содержимое рюкзаков/шалкеров и т.п. — сохраняются полностью и передаются покупателю без потерь.
- **Каталог рынка** — поиск, сортировка, пагинация, окно масштабируется под размер игрового окна/GUI Scale. Покупка — с выбором количества (не больше, чем есть в лоте).
- **Мои лоты** — список своих лотов, отмена своего лота с возвратом непроданного остатка (со всеми сохранёнными данными предмета).
- Покупка через терминал доступна всем, без подписки. Покупка тех же лотов **с сайта** требует у пользователя активной подписки с отдельным перком (переключается точечно на нужных грейдах в редакторе подписок в админке, а не привязано жёстко ко всем подпискам).
- Встроенная справка (кнопка «?») с пояснением механики рынка прямо в игре.

## Идемпотентность и «не жжём, пока не подтверждено»

Все мод-инициированные мутирующие вызовы (`atm_deposit`, `atm_withdraw`, `create_listing_direct`, `buy_mod`, `cancel_listing_mod`, `/crystal deposit`/`withdraw`) идут с `tx_id` (UUID), который мод генерирует при **старте** операции. Сайт дедуплицирует по `tx_id` — повтор с тем же `tx_id` просто возвращает сохранённый результат, ничего не выполняя заново.

При сетевой ошибке (таймаут/обрыв — то есть исход неизвестен, сайт мог и обработать запрос) мод обязан переиспользовать тот же `tx_id` на следующей попытке, а не сгенерировать новый — иначе, например, «Снять» спишет баланс дважды. Экраны и команды хранят `pendingTxId` per-player и на повторный клик/вызов после сетевой ошибки переигрывают ту же попытку, игнорируя новый ввод, пока не придёт определённый ответ. При явном отказе сайта (`ok:false`, не сетевая ошибка) — предметы/банкноты безопасно возвращаются игроку.

## Про нагрузку и утечки

- Ни у ATM, ни у терминала рынка нет `BlockEntity`/тикера — весь временный инвентарь живёт только в открытом меню (`AbstractContainerMenu`), закрытие меню возвращает несписанное игроку, как у ванильного верстака.
- HTTP-вызовы асинхронны через общий кэширующий пул daemon-потоков, не блокируют тик сервера.
- `RateLimiter` — общая карта на все вызовы `/crystal check`, а не по экземпляру на игрока; отдельный `ScheduledExecutorService` чистит неактивные записи каждые 10 минут.
- Кнопки блокируются флагом `busy` на время запроса — повторный клик не плодит параллельные запросы.

## Handshake

Отдельный обязательный (не `.optional()`) сетевой канал `crystalmod:handshake` — NeoForge сам требует совпадения мода на клиенте и сервере при подключении, без ручной проверки версий в коде мода.

## Настройка

После первого запуска появится `config/Xs_Crystal/config.json`:

```json
{
  "apiBaseUrl": "https://runes-and-rails.ru",
  "apiSecret": "change_this_to_the_site_api_secret"
}
```

`apiSecret` — отдельный секрет только для этого мода (`crystals_api_secret` в `config.php` сайта), не общий с другими модами сервера.

IP сервера должен быть в белом списке файрвола API сайта (админка → API firewall) — иначе критичные эндпоинты (`crystals-deposit`/`crystals-atm`/`crystals-verify`/`crystals-listing` в `FIREWALL_CRITICAL`, `api.php`) вернут `403`.

## Что осознанно не сделано

- Игрок офлайн при `/crystal give` — команда просто зафейлится, но RCON поверх TCP это не разрыв соединения, а обычный ответ; сайт его не разбирает и посчитает доставку успешной, хотя банкнота никуда не попала.
- Банкомат/терминал рынка не проверяют реальную дистанцию до блока (`stillValid` всегда `true`) — минимальная защита от читерского открытия меню без блока рядом, не критично для доверенного окружения.
- Лоток банкомата — фиксированные 5 слотов. Для очень больших сумм — несколько заходов, либо увеличить `TRAY_SIZE`.
