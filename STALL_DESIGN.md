# Торговый прилавок — 1.4.0

Крафт: пять досок и палка. Поставить над сундуком или бочкой. Запас остаётся в настоящем контейнере: прилавок не даёт бесплатного виртуального склада.

## Игроку

Владелец назначается при установке. Пустая основная рука + ПКМ открывают окно. «Выбрать товар» показывает инвентарь: выбирается только образец, предметы не изымаются. «Магазины» открывает список, создание/редактирование заявки, оформление, привязку и снятие привязки. Команды оставлены для совместимости; назначение товара выполняется через окно. Поддерживаются обычные предметы; имена, чары и содержимое контейнеров пока явно отклоняются. Пустые руки + ПКМ открывают окно. Владелец вводит цену за партию или за штуку (итог 1–30000) и размер партии числом (1–64). Посетитель покупает одну партию. Продавец может быть офлайн.

Перед оплатой проверяются расстояние, существование блока, неизменность предложения, запас и место в инвентаре. Изменение цены/товара требует открыть окно заново. Предметы не выбрасываются на землю при переполнении.

## Защита и нагрузка

У блока нет ticker, таймеров и фонового HTTP-опроса. Остаток считается при открытии/действии, не каждый тик. Окно использует штатную синхронизацию меню Minecraft. Клиент рисует один образец в пределах 24 блоков. Журнал записывается по событию продажи на отдельном I/O-потоке. Загрузка и принудительное сохранение не выполняются на server thread; текущая фаза кэшируется, повторные проверки не перечитывают файл.

Carry On: штатный тег data/carryon/tags/block/block_blacklist.json; Shift не используется для настройки. OPAC 0.29.3: точечная обработка публичного пустого ПКМ прилавка; настройка владельцем проверяется через API onEntityPlaceBlock. Защита сундука, установки и разрушения в привате сохраняется. При незавершённой сделке обычное разрушение прилавка дополнительно блокируется. Перенос Create/Sable в ходе сделки не проверен.

## Оплата и восстановление

Новый сайт-эндпоинт crystals_stall_api.php использует общий CrystalStalls.php и существующие users.crystals. Подключение — прежний apiBaseUrl/apiSecret в config/Xs_Crystal/config.json. Авторизация — отдельный ключ хрусталиков и существующий firewall crystals-listing. Таблица crystal_stall_trades хранит резерв и итог.

reserve: уникальный tx_id блокируется до списания денег, запрос привязан к неизменному хешу. commit: после выдачи товара продавцу начисляется цена за вычетом действующей комиссии сайта. refund: только отмена до выдачи. Все повторы идемпотентны. Ошибка хоста/невалидный ответ считаются неизвестным исходом; используется прежний tx_id.

Локальный журнал мира data/crystal-stall-transactions сохраняет участников, товар, координаты, сумму и фазу операции. Фаза applying после аварии требует ручной сверки; автоматической повторной выдачи и возврата нет. Сохранение инвентаря игрока и чанка Minecraft не является одной транзакцией с БД: аппаратный сбой в этот момент требует проверки. Журнал не удалять вслепую.

## Проверка

Настоящий клиент NeoForge 21.1.252, OPAC 0.29.3, Carry On 2.2.6.13; полная копия из 139 модов без DobbyMod. Продажа 8 железных слитков за 10 хрусталиков: бочка 64→56, инвентарь +8, продавцу +9, комиссия 1. Проверены двойной клик, полный инвентарь, устаревшая цена, возврат при закрытии окна, конкурентные повторы API и отклонение индивидуальных компонентов.

Сценарии src/testClient включаются только -PstallTest. Обычный jar их не содержит. Подробности, конфиг локального API, логи и пять скриншотов: VPS-Server-Minecraft/lab-local/STALL_MARKET_LAB.md. Прод и основной клиент не менялись.

## Магазины на сайте

Добровольная заявка на сайте /market/shops или в игровом окне: ПКМ по прилавку → «Магазины» → «Создать магазин». Выбор товара — кнопка «Выбрать товар», образец не расходуется. Обычный ПКМ владельца открывает окно и с предметом во второй руке; Shift + ПКМ остаётся Carry On. /crystal shop без аргументов открывает список магазинов; старые команды apply/list/link сохранены для совместимости. Привязка, отвязка и редактирование доступны кнопками без ручного ввода ID. Название, специализацию и оформление проверяет модератор; зарегистрированная карточка остаётся публичной до проверки изменений. Прилавки работают без регистрации и после её приостановки.

StallShops отправляет асинхронные снимки каталога по взаимодействиям, не чаще раза в 15 секунд; фонового HTTP-опроса и ticker нет. На сайте отображается время снимка. Работающие механизмы могут пополнять бочку/сундук под блоком: проверены обычная воронка и настоящая приводная лента Create 6.0.10 с латунной/андезитовой воронками. Прямое чтение Create Item Vault не добавлено. При выпуске 1.4.0 обновлять сервер и клиент вместе: обязательный сетевой протокол 3.

Сайт: CrystalShops.php, crystal_shops_api.php, market_shops.php, docs/CRYSTAL_SHOPS.md. Проверки — native HTTP, браузер (подача/одобрение) и настоящий Minecraft-клиент; исходники игровых сценариев остаются только в src/testClient.


## Проверка автоматического магазина Create

Короткий профиль (четыре основных jar) и полная сборка (139 модов без DobbyMod) прошли один сценарий: исходная бочка → латунная воронка с лимитом 1 предмет → лента 64 RPM → андезитовая воронка → бочка непосредственно под прилавком. Установка/подача используют настоящие блоки Create; в тесте мотор творческий, в обычной игре источник вращения может быть другим.

Локальный HTTP reserve специально задерживался на секунду. Проверено фактическое увеличение запаса, пока оплата ещё выполнялась, две покупки после опустошения, возврат при исчезнувшей бочке и повторная продажа после её восстановления. На один успешный прогон: четыре покупки по 8 предметов за 10, два возврата; покупателю 32 слитка, списано 40, продавцу 36, комиссия 4. Состояния и деньги независимо сверены в БД. Новых runtime-зависимостей и тикера у прилавка нет.

`StallCreateCheck` — только src/testClient, включается `-Dcrystalmod.stallCreateTest=true` вместе с основным сценарным флагом. Для повторов `launch_stall_sales.py --create` / `--create --full`, инструкция VPS-Server-Minecraft/MINECRAFT_CLIENT_TESTING.md. Результат требуется именно `STALLCREATE RESULT: PASS`. Прямой Item Vault и аварийное выключение компьютера не проверялись; физическая выдача и сохранение мира по-прежнему не являются одной транзакцией с MySQL.


## Исправления аудита и GUI — 1.4.0

Рабочие пулы ограничены: 4 потока/64 ожидающих задания для общего API, отдельно 4/64 для платежей прилавков, 2/32 для каталога; журнал — 1/128. Переполнение возвращает исключение через future, работа не переносится на вызывающий игровой поток. Новых потоков на каждый блок, ticker или фонового опроса нет. Журнал сериализуется до постановки в очередь; файл по-прежнему flush + atomic move. Сначала подтверждается durable request/applying, затем повторно проверяются меню, предложение, склад и вместимость перед физической выдачей. После выдачи durable delivered предшествует commit. Ошибка записи блокирует рискованную операцию для сверки. Общая транзакция мира и внешней БД этим не создаётся.

Образец товара передаётся вместе с открытием меню, чтобы смена товара не зависела от порядка обновлений блока. Загрузка журнала после NBT выполняется асинхронно. Пока грузится состояние или идёт сделка, редактирование запрещено. Если блок загрузился заново во время активной продажи того же UUID, чтение откладывается до её окончания, затем обновляются открытые окна. Синхронные файловые проверки существуют только в src/testClient/StallTestJournal. При работе с меню отсутствующий чанк не загружается принудительно.

В каталоге добавлена catalog_revision, в NBT — CatalogRevision. Старые, равные и запоздавшие публикации не отменяют более новое удаление. Удаление создаёт tombstone даже до первой публикации. Устаревшая привязка отклоняется. Сайт сам добавляет столбец существующей таблице. Новые клиенты дают возрастающую версию; старые запросы версии 0 не могут перезаписать версионную запись или воскресить удалённую legacy-запись.

Окна доступны через прилавок и /crystal shop без аргументов. В списке видна текущая привязка, есть постраничный просмотр; кнопка названия открывает редактор. В редакторе название, специализация, девиз, описание, цвет #RRGGBB, эмблема и обложка. После отправки — прежняя модерация на сайте. Новые пакеты не доверяют присланному владельцу/нику: сервер берёт игрока из соединения, проверяет активное меню, расстояние, UUID владельца и права OPAC для изменения товара. При наличии AuthMod требуется авторизованный незамороженный игрок. JSON клиентских форм читается как плоский объект без рекурсивного разбора; ответы привязаны к запросу и меню, поздние ответы закрытого окна игнорируются.

Регрессионный прогон --gui --create проверяет реальные окна: выбор образца без расхода предмета, создание/редактирование заявки, оформление, привязку/отвязку. Дополнительно: переполнение HTTP-очереди без CallerRuns, искусственно заблокированный I/O при продолжающихся тиках, coalesced загрузка журнала, загрузка блока во время активной сделки и отказ вложенному клиентскому JSON. Финансовая сверка выполняется отдельно по БД. --full добавляет весь набор 139 модов без DobbyMod. Релиз собирать без -PstallTest; сетевой протокол теперь 3, сервер и клиент обновлять вместе.

Пункт аудита о серверном секрете в клиентском конфиге в этот этап не входит: раздачу ключа и его ротацию нужно закрыть отдельно до общего запуска. Продовый сервер и основной клиент этим этапом автоматически не обновляются.
